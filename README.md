# codex-context-cleaner

Codex 本机上下文清洗工具。清理发往上游的推理历史与历史项标识，缓解 Responses 中转服务的兼容问题。

这是第三方工具。它清洗发送出去的请求，不会删除本地聊天记录，也不会解密数据。

## 功能

- 移除请求中的推理历史与历史项标识，保留消息内容、工具调用和文件引用。
- 支持 HTTP Responses 和流式输出（SSE）。
- 提供 macOS 与 Windows 启动入口，缺少 Python 时自动安装所需环境。

## 系统要求

- **macOS**：macOS 11 或更新版本，支持 Apple 芯片与 Intel 芯片。
- **Windows**：Windows 10/11，支持 x64、x86 与 ARM64。
- **客户端**：使用 HTTP Responses 协议。不支持 WebSocket。
- **上游服务**：需要可用的 API 地址和 API Key。

无需提前安装 Python。缺少环境时，首次启动需要联网下载；安装不需要管理员权限，也不会修改系统 PATH。

支持已有的 Python 3.9 或更新版本，启动前检查所需标准库。macOS 先检查 Homebrew、官方安装目录和系统 Python；找到可用环境后立即停止。没有可用环境时，再检查 PATH、Conda 环境记录与 uv 用户目录，不扫描整块硬盘。未安装开发工具时跳过系统 Python 占位入口。

每个 Python 入口最多检查 5 秒；卡住或检查失败就跳过。启动和设置共用安装锁，避免同时下载和替换运行环境。
macOS 新下载的 Python 首次执行会经过系统检查，此次验证最多等待 30 秒。

## 快速开始

### 1. 下载并解压

前往 [下载页面](https://github.com/solink7/codex-context-cleaner/releases/latest)，下载对应系统的压缩包：

- macOS：`codex-context-cleaner-macOS.zip`
- Windows：`codex-context-cleaner-Windows.zip`

完整解压后使用，不要直接在压缩包内启动。请选择上述文件，GitHub 自动提供的 `Source code` 压缩包不能直接使用。

### 2. 打开设置并填写地址

- macOS：双击 **设置代理.app**。
- Windows：双击 **settings.cmd**。

浏览器会打开本机设置页。填写你原来使用的上游 API 地址与本机端口，点击“保存设置”。首次使用不预设服务商，端口默认 `8787`，可以修改。

API Key 继续填写在客户端中，无需交给设置页。缺少 Python 时，启动入口会自动下载并安装；请保持启动窗口打开。

### 3. 启动代理

在设置页点击“启动代理”，等待状态变为“运行中”。也可以使用原来的入口：macOS 双击“启动代理.app”；Windows 双击 `start.cmd`。

设置页与代理使用不同的端口。即使代理未启动或端口被占用，仍能打开设置页修改配置。

### 4. 连接客户端

在客户端或 CC Switch 中填写：

- **API 地址**：复制设置页“客户端连接”中显示的地址，默认是 `http://127.0.0.1:8787/v1`
- **协议**：Responses
- **API Key**：你原来使用的上游 API Key

保存后新开一次聊天，发送消息确认连接正常。“代理已启动”只表示本机服务已就绪，上游地址与 API Key 仍需通过实际聊天验证。

## 日常使用

- **开始使用**：先启动代理，再使用已配置的客户端。
- **停止代理**：在设置页点击“停止代理”，或使用“停止代理.app” / `stop.cmd`。
- **修改配置**：在设置页修改并保存。代理运行时，“保存并应用”会重新启动代理；聊天回复尚未结束时，请等待后再操作。
- **更新版本**：先停止旧代理，解压新版本，再将原来的配置填入新版本。

新版本使用独立的运行目录，旧目录和日志会保留。macOS 的停止入口也可退出旧版代理。

关闭客户端或设置页不会停止代理。再次打开设置入口会回到同一个设置服务。重复启动不会创建第二个代理进程。运行期间请勿移动或删除工具文件夹。

## 配置说明

日常只需填写两个项目：

- **上游 API 地址**：实际的 API 服务地址，例如 `https://你的服务地址/v1`。不要填写本机代理地址。
- **本机端口**：默认 `8787`。修改后，重新复制客户端地址并在客户端中更新。

“高级设置”通常保持默认值：

- **等待超时**：每次网络读写的等待时间，默认 600 秒。
- **允许移除历史响应 ID**：默认关闭。只有确认客户端每次发送完整聊天历史时才开启；对应 `assume_full_history` 设置。

设置保存失败时，页面会显示原因。运行中应用新配置失败时，工具会恢复旧配置，并尝试重新启动原来的代理。

## 常见问题

### 无法下载或安装环境

先复用本机可用的 Python 3.9+，仅在未找到可用环境时下载。启动日志会记录选中的 Python 路径。

下载前先检查系统、芯片与下载连接。macOS 连接检查最多等待 20 秒；Windows 等待 15 秒。下载时显示下载量、速度和预计剩余时间；网速变化会更新估时，未知文件大小时显示“剩余时间待测速”。持续没有数据约 20 秒时退出，下载总时限为 30 分钟；不会反复从零自动重试。

- macOS：检查网络能否访问 GitHub。
- Windows：检查网络能否访问 python.org。
- 校验失败：检查网络后重新启动，工具不会安装校验失败的文件。
- 安装失败：检查剩余磁盘空间、文件权限和安全软件提示。

已安装的环境会保留，后续启动无需重新下载；聊天仍需联网访问上游服务。

### 提示端口被占用

打开设置页，换一个本机端口并保存，再重新启动代理。复制更新后的客户端地址，填回客户端。

### 代理已启动，但聊天失败

检查客户端是否使用本机 API 地址和 Responses 协议，再检查上游 API 地址、API Key 与网络连接。在设置页修改后点击“保存并应用”。

### 旧会话提示历史不可用

请新开会话。只保存在上游的历史、远端历史引用和加密压缩历史无法还原，工具会报错。

如果提示涉及 `previous_response_id`，请先确认客户端是否发送完整聊天历史，再按“配置说明”调整 `assume_full_history`。不确定时保持默认值。

### 去哪里查看错误日志

- **macOS**：在 Finder 按 `Command + Shift + G`，输入 `~/Library/Application Support/codex-context-cleaner/`，查看 `launcher.log`、`stdout.log`、`stderr.log`；设置入口日志为 `settings-launcher.log`，设置服务日志为 `settings.log`。
- **Windows**：打开解压目录中的 `.runtime` 文件夹，查看 `stdout.log`、`stderr.log`；设置入口的错误记录在 `settings.stderr.log`。

## 使用须知

- 清洗会移除推理历史，模型会失去对应的推理连续性。
- 工具只监听本机地址，不会开机自启，也不会自动修改客户端配置。
- 工具不保存 API Key，不记录聊天正文。客户端提供的认证信息会转发给你配置的上游服务。
- 上游连接失败或超时时，工具不会自动重试请求。
